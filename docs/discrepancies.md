# Журнал расхождений с проектом ЛР № 2

Каждое отличие реализации от документации ЛР № 2 и причина изменения. Этот же реестр
приведён на первой странице отчёта.

| № | Что в ЛР № 2 | Что реализовано | Причина |
|---|---|---|---|
| D-01 | Пароли ролей сервисов записаны в schema.sql литералами (`CHANGE_ME_*`); создаётся роль `svc_llm` | Блок ролей вынесен в `db/roles.sql`, пароли подставляются Liquibase из переменных окружения; `svc_llm` не создаётся | Секреты не должны храниться в репозитории (требование ЛР3); llm-orchestrator по условию ЛР3 не разворачивается |
| D-02 | Брокер RabbitMQ + DLQ (AMQP) | Apache Kafka 3.9 (KRaft, без ZooKeeper), SASL/PLAIN + ACL, топики `*.DLT` | Журнал событий с хранением и повторным чтением, порядок событий одной заявки по ключу, независимые группы потребителей (см. раздел 2.2 отчёта) |
| D-03 | Контейнер llm-orchestrator, OP-06/OP-11, кэш отчётов модели в Redis, связи B-10/B-11/B-12 | OP-06 и OP-11 отвечают `501 Not Implemented`; контейнер не разворачивается | Прямое исключение в условии ЛР3 |
| D-04 | Объектное хранилище (подразумевался MinIO) | SeaweedFS 3.97 с S3-совместимым API | Образы MinIO больше не публикуются в Docker Hub; S3-контракт (presigned-ссылки, права на бакет) сохранён |
| D-05 | B-03: загрузка `HTTPS PUT` по presigned-ссылке напрямую в хранилище | Presigned **POST** с политикой (ключ, `Content-Type`, точный размер, срок 15 мин); браузер обращается к хранилищу через reverse-proxy nginx своего веб-контейнера; порт хранилища наружу не публикуется | PUT-ссылка не позволяет хранилищу проверить размер и тип; хранилище не отдаёт CORS-заголовки. Файл по-прежнему не проходит через API-сервисы |
| D-06 | TLS на внутренних связях: SQL/TLS (B-05), RESP/TLS (B-06), AMQP/TLS (B-08/09), LDAPS (B-13), SMTP/TLS (B-14) | TLS — на внешней границе (api-gateway, HTTPS 8443; nginx → шлюз с проверкой сертификата). Внутри изолированных сетей Docker — без TLS; аутентификация сторон (пароли, ACL, SASL) сохранена | Локальное развёртывание на одном хосте; выпуск и ротация внутренних сертификатов не дают защиты внутри одной машины. Браузер ↔ nginx — HTTP на localhost (браузер считает localhost безопасным контекстом) |
| D-07 | OP-02 принимает `declared_grounds[]`, но в schema.sql нет ни столбца, ни справочника | Миграция `db/changes/001-declared-grounds.sql`: тип `support_ground`, столбец `applications.declared_grounds`, CHECK 1–9 оснований; поле возвращается в OP-01 | Иначе данные из контракта молча терялись бы; сотруднику основания нужны для проверки |
| D-08 | У `svc_applications` нет чтения `application_scores`, `protocols` | `GRANT SELECT ON application_scores, protocols TO svc_applications` | OP-01 возвращает `scores[]` сотруднику и заявителю после публикации итогов (наличие протокола) |
| D-09 | К Redis подключены auth, review, llm | Также api-gateway (счётчики лимитов, `rl:*`), applications (только чтение `session:*` + `enum404:*`), notifier (`notifier:*` — идемпотентность). Каждый со своим ACL-пользователем | Отзыв токена при выходе должен действовать во всех сервисах; Redis в ЛР2 и так заявлен как хранилище счётчиков лимитов |
| D-10 | — | В seed.sql у тестовых пользователей маркер `!bootstrap`; Argon2id-хеш с перцем вычисляет auth-service при первом старте | Готовый хеш в репозитории потребовал бы зафиксировать перец. В базе после запуска — только хеши |
| D-11 | Нет операции получения кампаний | Добавлен OP-17 `GET /campaigns` (кампании подразделения или открытые, с критериями) | Клиенту нужен `campaign_id` для OP-02 и критерии для OP-03; клиент должен обращаться только к API |
| D-12 | Заявка создаётся в статусе `draft`, но перехода `draft → submitted` нет | Добавлен OP-18 `POST /applications/{id}/submit` (идемпотентен) | Без него заявка не может попасть на рассмотрение |
| D-13 | OP-09 — одна строка без описания; нет регистрации и выхода | `POST /auth/password-reset` (запрос, всегда 202) + `POST /auth/password-reset/confirm` (одноразовый код); OP-14 `POST /auth/register`; OP-15 `POST /auth/logout` | ЛР3 требует регистрацию, полный сценарий восстановления и недействительность токена после выхода |
| D-14 | OP-05: «повторный ввод пароля не старше 5 минут» — механизм не описан | OP-16 `POST /auth/reauth` отмечает время в сессии Redis; review-service проверяет его, иначе `403 reauth_required` | Реализация требования контракта |
| D-15 | В сообщении брокера только идентификаторы; откуда notifier берёт адрес — не описано | В событие добавлен `recipient_id` (UUID); notifier получает адрес у auth-service (`GET /internal/users/{id}/contact`, сервисный токен) | ПДн не попадают в брокер; вызываемый сервис проверяет вызывающего |
| D-16 | В брокер публикует только applications-service | Также review-service (смена статуса после OP-03) и auth-service (письмо восстановления, топик с хранением 15 мин) | Статус меняет review-service; почта отправляется только notifier |
| D-17 | С каталогом R-09 связан только auth-service | applications-service тоже читает LDAP (учётная запись только для чтения) | OP-02: статус обучающегося сверяется на момент подачи |
| D-18 | B-15: передача подписанного реестра в бухгалтерию | Интеграция не реализуется; реестр фиксируется в `protocols`/`payout_entries`, ответ OP-05 содержит SHA-256; `registry_id = protocol_id` | R-10 — вне системы (ЛР1); отдельной таблицы реестров в schema.sql нет |
| D-19 | Коды для части ситуаций не заданы | OP-05: кампания чужой комиссии → 403; OP-02: неизвестная кампания или несовпадение вида → 400; повтор `Idempotency-Key` с другим телом → 422; некорректный UUID в пути → 404 | Уточнение контракта |
| D-20 | Политика токенов детально не описана | Access JWT RS256, 10 мин, только в памяти клиента; refresh 256 бит в cookie `HttpOnly; Secure; SameSite=Strict; Path=/api/v1/auth`, сессия 8 ч, ротация с обнаружением повторного использования | Уточнение политики, раздел 5 отчёта |
| D-21 | Лимит для OP-07 не задан | Вход — 20 попыток/мин с IP; регистрация — 5/ч; восстановление — 10/ч | Защита от перебора паролей |
| D-22 | — | Добавлены служебные контейнеры: `liquibase`, `kafka-init`, `kafka-ui`; заглушки `ldap` (R-09) и `mailpit` (R-08) | Миграции, топики и ACL, демонстрация сообщений; локальные заглушки внешних систем |
